# 内容架构与长期写作需求

## 文档状态

信息架构是内容如何分类、命名、互相关联、被导航和被搜索的整体规则。本文件记录当前
采用的轻量方案，不代表不可变的最终设计。用户已说明，后续可以根据实际前端展示方式
继续调整和细化；调整时必须同步更新本文和 `docs/BACKLOG.md`。

分类、栏目关系和评价字段的语义已经确认，可以作为后续页面和文章模板设计的起点。
定性推荐档位的名称和换算阈值留到实际前端展示设计时确定，它是展示细节，不再阻塞
内容模型。

## 内容范围与主要受众

```text
内容
├── 学习
│   ├── 秋招面试经历
│   ├── 人工智能智能体学习
│   ├── LeetCode 解题思路
│   └── 其他学习心得
├── 游戏
│   ├── 蔚蓝（Celeste）
│   │   ├── 模组地图推图记录与感受
│   │   └── 已游玩地图汇总与总体评价
│   ├── 我的世界（Minecraft）
│   │   ├── 模组玩法记录
│   │   └── 整合包体验与汇总
│   └── 其他 Steam 游戏记录
├── WOTA艺
│   ├── 我的作品
│   ├── 我喜欢的作品
│   └── 副歌技汇总
└── 动漫
    └── 按季度、剧场版或独立作品记录观看感受与分享
```

- 学习内容主要用于作者自己整理和回顾，可以更偏向高密度笔记，但仍应保留标题、日期、
  主分类、标签和来源等基本信息，确保以后能找到和理解。
- 游戏、WOTA艺和动漫内容具有明确分享目的。正文应让不掌握作者个人上下文的读者也能
  理解，并清楚标注作品来源、适用对象、剧透和主观评价。

人工智能智能体对应用户所说的 Agent，是能根据目标规划步骤、调用工具并执行任务的
程序。模组对应 Mod，是玩家或社区制作的游戏扩展内容。WOTA艺术语无需在公开博客中
额外设置科普说明；项目文档中的解释只服务于内部分类和开发沟通。

## 当前采用的轻量内容模型

“元数据”是写在文章开头、用于分类和生成列表的结构化信息，例如标题、日期和标签。
当前采用“一个主分类加多个标签”的模型：

- 主分类：`学习`、`游戏`、`WOTA艺`、`动漫` 四选一。
- 子主题：例如 `秋招面试`、`人工智能智能体`、`LeetCode`、`Celeste`、`Minecraft`。
- 标签：记录可跨分类复用的主题、技术、作品名、模组名或内容特征。
- 内容类型：区分普通记录、推图记录、解题记录、作品分享、评价和汇总。
- 状态：继续使用草稿与发布日期；需要时增加游玩、观看或完成状态。

一篇文章不同时归入多个主分类，以避免重复列表、网址不稳定和读者不知道应该从哪个
栏目进入。跨栏目关系通过标签和相关文章表达。例如一篇分析《我的世界》自动化模组的
学习文章，可以把主分类设为“游戏”，再使用“自动化”和“学习笔记”标签。

## 共用文章字段

以下字段用于未来扩展现有 Astro 内容集合，尚未修改代码：

| 字段 | 用途 | 当前决定 |
|---|---|---|
| `category` | 决定文章所属的主要栏目 | 必填，四个主分类之一 |
| `subcategory` | 表示栏目内的稳定子主题 | 选填，例如 Celeste |
| `contentType` | 区分记录、评价、汇总等页面用途 | 必填，具体词表在模板设计时细化 |
| `tags` | 支持跨主题查找和关联 | 保留现有能力 |
| `status` | 游玩、观看、解题或整理进度 | 按栏目选填 |
| `rating` | 作者对作品或体验本身综合质量的个人评价 | 十分制，允许小数 |
| `recommendationScore` | 作者愿意向目标读者推荐它的程度 | 十分制，允许小数，考虑受众匹配和入门门槛等因素 |
| `recommendationLabel` | 在卡片或汇总表中快速表达定性推荐档位 | 从推荐度自动换算；档位名称和阈值在前端设计时确定 |
| `spoiler` | 提醒文章是否包含剧透 | 游戏和动漫使用布尔值 |
| `sourceLinks` | 指向题目、地图、整合包或作品来源 | 建议使用，格式在模板设计时确定 |

这里的“浮点”表示可以记录带小数的数值，例如 `8.5`。字段名只是便于讨论的暂定技术
名称；在含义确定前，不加入内容校验。字段也不应一次全部强制填写，只把确实用于导航、
汇总或搜索的字段设为必填，避免短记录变成复杂表单。

## 各栏目当前规则

### 学习

- 秋招面试经历：可记录年份、目标方向、流程阶段、题目类型、复盘和建议。
- 人工智能智能体学习：可记录概念、工具或模型、资料来源、实践结果和适用版本。
- LeetCode 解题：可记录题号、题名、难度、使用语言、核心思路、时间复杂度、空间
  复杂度和代码。
- 学习内容主要自留自用，因此不强制每篇都写面向新读者的完整背景介绍。
- 面试内容默认匿名化，不公开可识别公司、面试官、个人或未公开流程的信息；不得发布
  受保密要求约束的题目原文。以后确需公开具体名称时，应逐篇确认。

### 游戏

- Celeste 单篇推图记录：地图名、作者、来源、难度、完成状态、游玩日期和个人感受。
- Celeste 汇总页：从单篇文章元数据生成地图表格，避免在文章和表格中重复维护数据。
- Minecraft 单篇记录：游戏版本、模组加载器、模组或整合包名称与版本、游玩阶段和
  体验评价。
- 其他 Steam 游戏：游戏名、游玩状态、日期、评价和相关文章。
- 客观或社区常用难度、个人评分、个人推荐度和定性推荐档位必须分开，不能互相替代。
- 包含关键剧情、地图机制解法或其他可能影响初见体验的内容时，使用剧透字段并在正文
  前给出提醒。

### WOTA艺

- 保持三个并列入口：我的作品、我喜欢的作品、副歌技汇总。
- 企划和技连作为 WOTA艺作品的呈现形式，用于描述“我的作品”或“我喜欢的作品”，
  不额外提升为全站主分类。
- 副歌技是 WOTA艺的基础组成部分；汇总条目以后可以关联采用该副歌技的作品。
- 我的作品可记录发布时间、参与者、使用曲目、作品形式、相关技和外部作品链接。
- 我喜欢的作品可记录作品来源、作者或企划、喜欢的原因、作品形式和关联技。
- 外部作品必须保留作者或发布者、原始链接和必要署名，不默认转载完整媒体文件。
- 公开博客不专门解释 WOTA艺、企划、技连和副歌技；目标读者按已了解这些概念设计。

### 动漫

- 一条记录对应一个季度、剧场版或独立作品；单集感想放在对应记录内部，不默认创建
  单集级页面。
- 可记录作品名、季度或年份、观看状态、观看日期、感受、评价和剧透标记。
- 汇总页从单篇记录读取观看状态、评分和推荐度，不手工复制相同数据。
- 涉及剧情信息时使用剧透字段，并在列表或正文入口处提醒读者。

## 导航与查找

采用较小的全站导航：`首页`、`文章`、`关于`，并保留搜索入口。在“文章”页和首页
显著展示 `学习`、`游戏`、`WOTA艺`、`动漫` 四个栏目入口。这样可以加强扩展性，未来
增加子主题时不需要持续扩张顶部导航。

每个栏目页负责：

- 显示栏目说明、最新文章和稳定子主题。
- 提供相关汇总页，例如 Celeste 地图汇总。
- 允许通过标签继续细分。
- 为从搜索或外部链接进入的读者显示当前位置和返回栏目入口。

现有 Pagefind 搜索继续覆盖全部公开文章。Pagefind 是构建网站时生成的静态全文搜索
工具，不需要数据库。内容量较少时不增加复杂筛选；文章明显增多后，再考虑按主分类、
游戏或内容类型过滤。

## 网址规则

界面标签使用中文，网址采用稳定的英文小写路径，例如：

- `/posts/learning/...`
- `/posts/games/celeste/...`
- `/posts/games/minecraft/...`
- `/posts/wota/...`
- `/posts/anime/...`

迁移时不保留旧文章网址，也不为旧网址增加重定向。这样实现和维护最简单，但已有书签、
搜索结果或外部引用会失效；用户已接受这一影响。具体迁移仍属于后续开发任务，本轮不
修改任何文章路径。

## WOTA艺内部检索结论

本轮检索仅用于开发团队理解，不作为博客科普内容。公开资料通常把技连视为一种组合式
作品或表演形式，也把企划视为围绕曲目组织的完整作品；副歌技则可以作为作品中的基础
组成单元。这个理解支持当前“作品入口记录呈现形式、副歌技单独汇总并关联作品”的轻量
模型。若公开资料与作者实际用法冲突，以作者定义为准。

## 查找场景

未来结构至少应支持：

1. 已知目标：直接找到某张 Celeste 模组地图的游玩记录和评价。
2. 浏览比较：查看所有 Minecraft 整合包体验并比较版本、状态、评分和推荐度。
3. 探索内容：从某个 WOTA艺作品进入相关作品形式或副歌技汇总。
4. 搜索恢复：关键词没有结果时仍能返回四个栏目或查看相关标签。

## 已确认的当前方案

- IA-001 受众：学习内容以自用为主；游戏、WOTA艺和动漫以公开分享为主。
- IA-002 导航：使用小型全站导航，四个内容栏目通过首页和文章页进入。
- IA-003 归属：每篇文章一个主分类，允许多个标签。
- IA-004 网址：页面显示中文，网址使用英文小写路径，不保留旧网址。
- IA-005 WOTA艺：不做公开术语解释；三个内容入口并列，作品形式和基础技通过字段及
  关联表达。
- IA-007 安全：面试内容默认匿名化；游戏和动漫采用文章级剧透标记与阅读前提醒。
- IA-008 动漫粒度：按季度、剧场版或独立作品建记录，单集内容收在记录内部。

这些决定是当前可实施基线，不妨碍后续按实际前端效果调整。

## 已确认的评价规则

### IA-006：评分、推荐度与定性档位

同时保留以下三种个人评价，而且评分与推荐度不是同一个概念：

1. 评分是作者对作品或体验本身综合质量的个人评价，采用十分制并允许小数。
2. 推荐度是作者愿意向目标读者推荐它的程度，采用十分制并允许小数；它会考虑受众
   匹配、入门门槛等因素，所以可能与评分不同。
3. 定性推荐档位从推荐度自动换算，避免文字档位与数值互相矛盾。

定性档位的具体名称和数值阈值在设计游戏或动漫汇总页时结合实际版面确认。该细节只
影响显示文案和换算函数，不改变文章需要保存的评分与推荐度数据，因此不阻塞栏目开发。

## 本轮非目标

- 不创建栏目页面、筛选器或新的文章模板。
- 不迁移文章目录或修改网址。
- 不引入数据库、内容管理系统或服务端搜索。
- 不实施评分字段、档位换算或汇总页展示。
