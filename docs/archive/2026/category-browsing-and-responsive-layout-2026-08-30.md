# 栏目浏览与响应式布局完成记录

## 问题与结论

用户提供的 2560 级 Edge 桌面截图没有出现文字截断或横向溢出，但栏目页、页头和页脚
都沿用了约 48rem 的文章正文宽度，导致浏览页面在宽屏上信息密度过低。问题不是传统的
“移动端破版”，而是阅读页面和浏览页面使用了同一种容器。

本轮保留正文的舒适行长，把栏目浏览框架扩大到约 72rem。栏目页在宽屏显示“浏览此栏目”
侧栏和文章结果主栏，在中小屏按源码和键盘顺序堆叠为单栏，不使用视觉重排改变阅读顺序。

## 已完成范围

- 页头、页脚和栏目浏览页面使用约 72rem 的外壳宽度；文章详情仍保持约 48rem。
- 栏目页自动统计并展示主题标签、内容类型和发布年份，每个入口显示文章数量。
- 新增栏目内静态浏览网址：
  - `/posts/<栏目>/tags/<标签>/`
  - `/posts/<栏目>/types/<内容类型>/`
  - `/posts/<栏目>/archive/<年份>/`
- 每种浏览方式都有总览页和结果页；结果状态保存在网址中，不依赖 JavaScript 才能
  查看，面包屑的中间路径也不会指向不存在的页面。
- 当前学习栏目可通过“程序设计语言原理”、内容类型“笔记”和“2025年”进入两篇文章。
- 空栏目不生成空结果网址，并在浏览侧栏说明发布文章后会自动出现入口。

## 响应式和可访问性验证

使用本地开发服务器和浏览器视觉检查覆盖 390×844、768×1024、1280×900 和
2559×1599 四组目标窗口：

- 390 和 768 目标宽度为单栏；浏览方式和文章结果按同一逻辑顺序显示。
- 1280 和 2559 目标宽度为双栏；浏览栏实际为 288px，结果栏实际为 792px。
- 各尺寸的文档滚动宽度均未超过可用视口宽度，没有横向溢出。
- 手机尺寸下，四个栏目入口和四个浏览入口的实际高度均为 44px。
- 当前项同时使用填充背景、下划线和 `aria-current="page"`，不只依赖颜色表达。
- 语义快照确认存在主导航、面包屑、主内容、补充导航、分级标题、文章列表和页脚。
- 浅色、暗色主题都已截图复核；文章详情在 1280 目标宽度下仍为 768px 最大宽度。

视觉证据保存在工作区外的 Codex 可视化目录 `responsive-audit` 中，避免把开发截图发布
到 GitHub Pages。
