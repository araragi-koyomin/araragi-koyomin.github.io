## P1：文章编写体验

### AUTHOR-001 — 试用 Front Matter CMS

- 状态：`in_progress`
- 编号说明：`AUTHOR` 表示只服务于作者本地写作流程、不作为公开网站功能发布的事项。
- 目标：在 VS Code 中试用 Front Matter CMS，为 `src/data/blog` 提供结构化字段编辑、
  文章模板、标签与子主题选择、媒体管理和本地 Astro 页面预览。
- 范围：安装本地 VS Code 扩展并提交可共享的项目配置；不增加线上 `/admin` 页面、
  服务端、数据库、自动 Git 提交、推送或部署。
- 体验结论：由用户实际使用后决定保留、调整或移除；在用户确认前不把扩展设为长期
  唯一写作方式。
- 当前进度：已本地安装 Front Matter CMS `10.12.0`，并加入共享配置、文章模板、扩展
  推荐和 Markdown 快捷片段；配置键已与该版本扩展声明逐项核对。用户已通过 CMS 创建
  第一篇 Minecraft 整合包草稿，字段面板能够生成主栏目、子主题、内容类型、标签和进度
  等有效字段；Celeste 合集注册表和条件字段已经加入配置，但尚待真实操作确认。媒体导入
  和 Astro 页面预览仍待实际体验。
- 已知试用边界：当前目录选择仍由作者完成；`draft: true` 文章尚无安全的本地详情预览；
  本次草稿实际落在 `src/data/blog/minecraft`，没有自动遵循约定的
  `src/data/blog/games/minecraft` 层级；扩展首次启动可能生成 `.frontmatter/database`
  索引文件，提交前必须先检查。
- 完成证据：扩展能够识别当前文章和内容字段，用户完成实际体验并明确是否保留；结论
  和配置处置记录进入冷层归档。

### AUTHOR-002 — 完成文章编写必备辅助能力

- 状态：`in_progress`
- 目标：无论最终采用 Front Matter CMS、项目脚本还是专用扩展，都必须支持从现有标签
  中搜索选择、子主题注册表、图片导入、从已有文章搜索并插入内部链接、代码块/数学公式/
  来源链接快捷插入，以及修改旧文章时建议填写 `modDatetime`。
- 其他已确认能力：按栏目和内容类型生成可编辑模板、条件显示 WOTA艺分区、检查必填
  Frontmatter、重复网址和图片路径、显示实际文章网址、打开 Astro 热更新预览、支持
  发布前检查但不自动执行 Git 或部署操作。
- 目录约定：新文章先统一放入 `src/data/blog/<主栏目>/<子主题>/`；现有文章不在本事项
  中自动迁移。`slug` 自动生成和命名策略暂缓，不阻塞其他写作辅助能力。
- 当前已配置：已有标签选择、7 项初始子主题注册表、WOTA艺条件字段、媒体库与粘贴导入
  入口、代码块/行内与块级数学公式/Markdown 链接片段、结构化来源链接字段、显式更新
  `modDatetime` 的命令入口、真实 Astro 预览地址，以及 Celeste 合集数据文件选择字段。
  图片最终路径、新增标签和合集选择的实际交互仍需在 VS Code 中验收。Celeste 合集注册表
  已配置为可在 Front Matter CMS“数据”面板中增删条目的多记录 JSON 文件；文章编辑面板的
  `celesteCollection` 字段只负责搜索和选择已有合集，不直接创建新合集。
- 已解决的使用问题：`journeys-of-a-bygone-wanderer.md` 最初填写了未注册且含大写字母的
  `celesteCollection: SSC2024`，会触发 Astro 内容校验错误。作者后来在合集注册表新增
  `ssc-2024` 并从文章中引用该稳定编号；文章现已公开并通过生产构建。
- 当前新增：根据首篇“春葬”记录提炼 Celeste 地图专用 Markdown 模板，明确区分供汇总页
  读取的 Frontmatter 字段与自由书写的正文，避免只在正文填写评分而导致汇总数据缺失。
  首次用该模板创建草稿时发现：直接写在模板文件中的 `{{now}}` 不会按内容字段默认值
  处理，而是原样进入 Markdown，导致 Astro 无法把发布日期解析为日期。现已改为
  Front Matter CMS 明确支持的自定义模板占位符，并修正该草稿的无效日期；下一次实际
  新建文章时仍需确认扩展会正确展开新占位符。
- 尚未满足：按标题搜索已有文章并插入内部链接、编辑旧文章时主动提醒更新时间、按主栏目
  联动过滤子主题、自动建立 `<主栏目>/<子主题>` 目录，以及不进入生产输出的草稿预览。
  这些仍是必做能力，不能因本轮已有基础配置而视为完成。
- 依赖：先完成 AUTHOR-001 的试用；能够由 Front Matter CMS 稳定实现的能力优先使用
  现成扩展，不能满足的部分再以项目脚本或 VSIX 扩展补齐。
- 完成证据：每项必做能力都有可重复的用户操作路径和验证记录，生成的文章能通过 Astro
  内容校验，且不会覆盖现有正文或未经确认改变 Git 状态。
