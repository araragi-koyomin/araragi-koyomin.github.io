# 文章编写辅助工具方案

## 目标

在不改变 Markdown 作为内容源、不引入线上服务端和不自动操作 Git 的前提下，减少新建、
分类、补充 Frontmatter、插入媒体、关联文章和预览内容时的重复操作。最终工具必须让作者
仍能直接打开和编辑普通 `.md` 文件，不产生只能由某个扩展读取的专有正文格式。

## 当前试用决定

第一阶段先试用运行在 VS Code 内的 Front Matter CMS。用户完成实际写作体验后，再决定
保留、调整或移除；本阶段不开发完整 VSIX 扩展，也不在公开网站增加 `/admin` 页面。

试用配置应覆盖：

- 将 `src/data/blog` 识别为文章目录。
- 使用当前 Astro 内容接口编辑标题、日期、主栏目、子主题、内容类型、标签和可选评价
  字段。
- 只在主栏目为 WOTA艺时显示并要求填写 `wotaSection`。
- 使用 `pnpm dev` 启动本地站点，并以 `http://127.0.0.1:4321` 作为真实页面预览来源。
- 提供可编辑文章模板，不重写现有两篇 `copl` 正文。
- 关闭或不启用自动 Git 提交、推送和发布功能。

## 当前实现状态

已安装 Front Matter CMS `10.12.0`，项目配置位于仓库根目录的 `frontmatter.json`，新文章
模板位于 `.frontmatter/templates/blog.md`。VS Code 扩展推荐和普通 Markdown snippet 也
已加入项目配置；即使暂时关闭 Front Matter CMS，代码块、数学公式和文章 Frontmatter
框架仍可通过 VS Code snippet 使用。

模板文件名前缀已显式留空，由作者输入文件名；没有配置自动 slug 模板。现有文章中的
`slug` 只作为隐藏兼容字段保留，试用期间不生成、不改写，也不会批量迁移旧文章。

Celeste 地图另有专用模板 `.frontmatter/templates/celeste-map.md`。在 VS Code 命令面板
执行 `Front Matter: 从模板创建新文章`，选择 `celeste-map`，再把文件保存到
`src/data/blog/games/celeste/`。模板默认保持草稿并提供地图字段和正文标题；地图合集默认
为“独立地图”，创建后必须按实际情况重新选择。模板中的发布日期使用项目自定义占位符
`{{publicationDateTime}}`，由 CMS 再转换为当前时间。

本轮配置已经提供：

- 与 Astro 内容集合一致的主栏目、内容类型、评分、推荐度、剧透和来源链接字段。
- 独立的文章顶部封面图、必填替代文字和可选说明文字字段；社交分享图继续单独维护。
- 只有主栏目为 `wota` 时显示的 `wotaSection` 条件字段。
- `subcategory` 为 `celeste` 时显示合集、地图难度和主要 gameplay 字段；合集可从
  `src/data/celeste-collections.json` 集中注册表搜索选择，文章只保存合集稳定编号。
- 可搜索选择的标签字段，以及包含 7 个初始值的 `subcategories` 自定义分类注册表。
- 媒体库、剪贴板图片导入入口和要求填写替代文字的媒体元数据字段。
- 代码块、行内与块级数学公式、普通 Markdown 链接和常用正文结构片段。
- 显式执行“更新最后修改时间”的入口；全局自动更新时间保持关闭，避免保存时静默改写。
- `pnpm dev` 和 `/posts/{{pathToken.relPath}}` 对应的真实 Astro 页面预览配置。

仍需通过实际体验或后续专用实现完成：

- Front Matter CMS 当前不提供符合本项目要求的“按标题搜索文章并插入站内链接”完整流程；
  普通链接片段不是该能力的替代品。
- 修改旧文章时目前可以手动更新时间，但还没有在适当时机主动建议填写 `modDatetime`。
- 子主题注册表当前是全局列表，还没有随主栏目联动过滤，也不会自动创建目录层级。
- Celeste 合集选择字段已经配置，但仍需作者在 Front Matter CMS 中完成一次真实新增和
  选择操作，确认该版本扩展的搜索与保存体验。
- 媒体粘贴与自定义 `@/assets/images/...` 路径必须通过一次真实图片导入验证。
- 文章封面布局已经实现，但还需要用第一张真实封面图片确认 Front Matter CMS 保存路径、
  桌面与手机裁切和说明文字显示。
- `draft: true` 仍会被当前 Astro 路由过滤，草稿详情预览需要单独设计。

## 内容目录约定

新文章暂时统一使用：

```text
src/data/blog/<主栏目>/<子主题>/<文件名>.md
```

主栏目目录使用 `learning`、`games`、`wota`、`anime`。子主题使用稳定的小写英文标识，
但允许从注册表选择或在确认后新增。现有 `src/data/blog/copl` 不在本阶段迁移。

`slug` 的自动生成和中文标题转换策略暂缓。试用阶段不自动翻译、转拼音或批量重写已有
`slug`；创建新文章时仍需有可用文件名，具体命名先由作者输入或沿用扩展默认交互。

## 必做能力

以下能力不因 Front Matter CMS 的试用结果而取消；现成扩展无法稳定实现时，由项目脚本
或专用 VSIX 扩展补齐。

| 能力 | 最低验收行为 |
|---|---|
| 从现有标签中搜索选择 | 输入时显示已有标签，可多选并允许新增，避免大小写或文字变体造成重复 |
| 子主题注册表 | 按主栏目显示已有子主题，可新增并保存为以后可选择的稳定值 |
| 图片导入 | 选择本地图片后复制到约定目录，生成安全文件名，要求填写替代文字并插入正确 Markdown 路径 |
| 内部链接选择 | 可按标题搜索已有文章，插入正确的站内链接，不要求手工记忆网址 |
| 快捷插入 | 支持代码块、行内/块级数学公式、来源链接和常用文章结构，且不破坏现有 Markdown 语法 |
| 修改时间建议 | 编辑旧文章时清楚提示可以更新 `modDatetime`，但不在未确认时静默改写文章 |

其他目标包括条件字段、评分与推荐度范围提示、剧透设置、重复网址检查、图片路径检查、
文章最终网址展示、真实 Astro 热更新预览和发布前检查。

## 字段分组

创建文章时优先显示当前任务必需的信息：标题、发布时间、主栏目、内容类型、子主题、
标签和摘要。作者、评分、推荐度、状态、剧透、来源链接、分享图等放在扩展字段区域。

- WOTA艺：显示 `wotaSection`，三个值分别为我的作品、我喜欢的作品、副歌技汇总。
- 游戏和动漫：优先显示剧透、评分、推荐度与状态，但不强制短记录填写评价。
- Celeste 地图：选择 `subcategory: celeste` 后填写地图合集、地图难度和主要 gameplay；
  地图名使用 `title`，简评使用 `description`，总体评分使用 `rating`。草稿可以暂时缺少
  上述字段，改为公开文章前必须补齐，否则 Astro 内容检查会明确报错。
- 学习：默认内容类型为笔记，仍允许题解、经历和汇总。
- 标签和子主题：使用可搜索选择，不使用只能输入且无法发现已有值的自由文本框。

## 预览与草稿边界

正文渲染继续以 Astro 页面为准，不重新实现一套可能与 KaTeX、Shiki 或主题样式不一致的
Markdown 渲染器。保存文件后由 Astro 开发服务器热更新，编辑工具负责打开或刷新对应
网址。

当前 `draft: true` 文章不会生成正常详情路由，而未来发布日期也不能作为安全保密手段。
正式完善草稿预览时，应保证草稿仅在开发环境可访问、页面有醒目标识，并在生产构建、
RSS、搜索、OG 图片和 sitemap 中全部排除。

## 文章顶部封面图

需要在标题与正文之间显示封面时，在 Front Matter CMS 中填写以下字段：

```yaml
heroImage: ../../../../assets/images/示例图片.webp
heroImageAlt: 对图片可见内容的简洁说明
heroImageCaption: 可选的图片来源或补充说明
```

`heroImage` 从项目媒体库 `src/assets/images` 中选择；相对路径的层级由文章所在目录决定，
优先通过 CMS 选择图片而不是手写路径。公开文章设置图片后，`heroImageAlt` 必须填写，
它让图片加载失败或使用屏幕阅读器的读者仍能理解图片内容。`heroImageCaption` 可省略。

封面会固定显示在文章日期和结构化元数据之后、Markdown 正文之前，并在桌面和手机上使用
16:9 比例裁切。没有填写 `heroImage` 时不显示空占位。`ogImage` 仍然只控制社交平台的
链接预览图片；如果希望同一张图片同时承担两种用途，需要分别设置两个字段。

### 首张真实封面验证

“春葬”使用 `src/assets/images/games/celeste/chun-zang-cover.png` 作为第一张真实文章封面。
该文件是作者提供的 1858×1114 PNG 原图副本，复制前后 SHA-256 校验值一致，没有压缩或
改写原文件；开发预览由 Astro 自动生成多尺寸 WebP 供浏览器选择。

桌面 1440 像素视口下，封面实际显示约为 736×414；手机 390 像素宽度下显示约为
343×193。两端均保持 16:9、居中裁切，森林中的角色和白色相框仍完整可辨，没有页面横向
溢出或浏览器脚本错误。文章已填写描述画面内容的 `heroImageAlt`，没有来源或说明信息时
不填写 `heroImageCaption`。

## 管理 Celeste 地图合集

`celesteCollection` 在文章编辑面板中是“从已有合集搜索选择”的字段，不直接承担创建
合集。新增合集时，在 VS Code 命令面板运行 `Front Matter: Open data dashboard`，进入
“Celeste 地图合集”，再新增一条记录并填写：

- `id`：不会随显示名称变化的稳定编号，只允许英文小写字母、数字和连字符，例如
  `ssc-2024`。
- `name`：页面展示的完整合集名称。
- `color`：从 `neutral`、`sky`、`violet`、`rose`、`amber`、`emerald` 中选择一个标记颜色。

保存数据记录后，再回到文章的 `celesteCollection` 字段搜索并选择它。文章只保存 `id`，
公开表格从 `src/data/celeste-collections.json` 统一读取显示名称和颜色。

当前草稿 `journeys-of-a-bygone-wanderer.md` 中的 `SSC2024` 尚未注册，并且包含大写字母，
因此不符合项目稳定编号规则。确认该合集的显示名称与颜色后，应先新增合集记录，再把草稿
改为数据面板中实际保存的编号；在此之前保持草稿状态。

## VSIX 备选方案

若 Front Matter CMS 不能满足项目字段、目录、图片路径或真实预览要求，再开发专用 VSIX。
优先使用 VS Code 原生选择框、输入框、诊断和文件编辑接口；只有元数据侧栏确有价值时
才增加网页视图，不首先替换普通 Markdown 编辑器。

专用扩展必须可在不发布到市场的情况下安装和卸载，配置与模板保存在仓库中，扩展删除后
文章仍是完整可编辑的 Markdown。

## 安全与可撤回性

- 不自动提交、推送、切换分支或部署。
- 不保存 GitHub 令牌或其他秘密。
- 不静默覆盖非空 Markdown、现有图片或用户未保存内容。
- Front Matter CMS 试用失败时，可以移除扩展和试用配置，不需要迁移正文格式。
- 删除、批量改名、批量标签替换等操作不作为第一阶段默认能力。

## 待体验后决定

- Front Matter CMS 的字段面板是否比直接编辑 YAML 更顺手。
- 内容面板、标签管理和媒体管理是否会产生过多额外文件或工作区噪声。
- 真实站点预览能否正确处理“目录加文件名或 slug”的现有网址规则。
- 必做能力中哪些可以通过配置完成，哪些值得进入专用 VSIX。

## 实际试用记录

### 2026-08-30：创建第一篇 Minecraft 整合包草稿

用户已经通过 Front Matter CMS 创建《新星工程》草稿。CMS 能够生成并编辑标题、草稿、
标签、栏目、子主题、内容类型和进度等字段，说明基础元数据流程可以使用。

本次试用同时确认：CMS 没有根据 `category: games` 和 `subcategory: minecraft` 自动建立
约定目录；创建时仍需要作者自行选择或整理目录。当前文章已经位于
`src/data/blog/games/minecraft`，但目录自动建立仍属于 AUTHOR-002 的未完成能力。

Minecraft 整合包文章的正文采用轻量记录方式：保留基础信息、必要的作者背景和阶段小标题，
阶段内以自然段记录感受，不强制拆分目标、资源、卡点、解决方案等攻略式条目，也不要求记录
开始时间和累计游玩时间。

### 2026-08-30：创建第一篇 Celeste 地图草稿

已创建 `src/data/blog/games/celeste/chun-zang.md`，地图名为“春葬”。文章使用
`celesteCollection: canvas-contest` 引用“画布竞赛（Canvas Contest）”合集，并填写
难度“画布紫/酱五绿”和主要 gameplay“冰块刷新机制、果冻水晶”。合集显示名称和紫色
标记保存在集中注册表中，没有复制到文章 Frontmatter。

作者随后补充了正文并取消草稿状态。第一次公开尝试没有进入前端，原因是正文里的
“评价：6.0/10.0”和“推荐度：7.5/10.0”只是普通文字，汇总页不会从自然语言反向猜测
结构化数据；公开 Celeste 文章又缺少必填的 `rating`，因此 Astro 内容校验拒绝加载。

现已将正文中明确写出的评价同步为 `rating: 6.0`、`recommendationScore: 7.5`，并用作者
正文中的总结句更新 `description`。以后表格所需的合集、难度、主要 gameplay、评分和
简评必须写在 Frontmatter；正文可以自由展开，但不作为表格数据源。由此提炼的专用模板
不预填 `0` 分，避免把“尚未评分”误写成真实的零分。

### 2026-08-30：验证 Celeste 专用模板日期

作者使用专用模板创建 `journeys-of-a-bygone-wanderer.md` 时发现，模板文件里直接书写的
`{{now}}` 被原样保存，随后又被 CMS 解析成对象，Astro 因此不能把 `pubDatetime` 当作
日期，并让整个内容集合显示错误遮罩。

原因是 `{{now}}` 属于 Front Matter CMS 内容字段 `default` 等配置位置支持的默认占位符，
并不直接作为原始 Markdown 模板正文的动态日期。当前配置新增自定义占位符
`publicationDateTime`，其值再引用 `{{now}}`，模板则使用 `{{publicationDateTime}}`；这
符合 Front Matter CMS 关于“自定义占位符可以在模板中使用，且静态值可以包含其他占位符”
的规则。已生成草稿只把无效发布日期恢复为有效时间值，标题、草稿状态和正文没有代写。

该草稿仍是 `draft: true`，不会进入 Celeste 公开汇总。下次从模板创建新文章时，需要确认
`pubDatetime` 已直接变成 ISO 日期字符串；如果仍看到双花括号，应先保持草稿并修复日期，
不要启动发布。
